# 효소 궤적 (Enzyme Trajectory)

수식 `y = f(x)`로 궤적을 설계하는 게임입니다. 1부(고1 통합과학)에서는 **효소를 쏘아** 활성화 에너지 장벽을 넘기며 효소의 성질을 배웁니다. 2부(생명과학 심화)에서는 **분자를 쏘아** 효소 관문을 차례로 통과시키며 TCA 회로의 물질·에너지 수지를 배웁니다.
수식으로 탄도를 만드는 그래프 사격 장르(예: *Graphwar*)의 메커니즘을 빌려 왔고, 판정 규칙은 효소 개념 하나로 통일했습니다.

> **반응 성공 ⇔ 분자 에너지(온도) ≥ 유효 활성화 에너지**
> 유효 활성화 에너지는 *맞는 기질 · 변성되지 않음 · 알맞은 pH* 세 조건을 모두 갖춘 효소가 있을 때만 낮아집니다.
> 효소는 에너지를 주지 않습니다. 장벽을 낮출 뿐입니다.

서버가 필요 없는 정적 웹앱입니다. `index.html`을 브라우저로 열기만 해도 동작합니다.

## 스테이지

| # | 제목 | 핵심 개념 | 새로 등장하는 규칙 |
|---|------|-----------|--------------------|
| 1 | 조준 훈련 | 효소는 반응 후에도 변하지 않는다(촉매) | 수식 궤적, 한 발로 여러 기질 분해 |
| 2 | 기질 특이성 | 효소는 정해진 기질에만 작용 | 맞지 않는 기질에 부딪치면 정지 |
| 3 | 활성화 에너지 | 효소는 장벽을 낮출 뿐 에너지를 주지 않는다 | 온도 조절, "효소 없이 가열", 발사 전 예측 |
| 4 | 뜨거운 구역 | 효소는 단백질이라 고온에서 변성 | 70°C 구역을 지나면 비가역 변성 |
| 5 | 소화관의 pH | 효소마다 최적 pH가 다르다 | 위(pH 2) · 소장(pH 8) 구역 |
| 6 | 종합 임무 | 종합 | 발사 전 에너지 도표 가림 + 예측 |

### 2부 · 물질대사: TCA 회로 (생명과학 심화)

2부에서는 메커니즘이 뒤집힙니다. **발사체는 기질 분자이고, 효소는 필드에 고정된 관문**입니다.
분자는 자기를 기질로 삼는 관문을 지날 때마다 다음 중간 산물로 바뀝니다. 그때 CO₂가 나가고, NADH·FADH₂·ATP(GTP)가 생기고, 물이 들어갑니다.
맞지 않는 관문이나 억제된 관문에 닿으면 튕겨 나갑니다. **궤적이 관문을 지나는 순서가 곧 대사 경로의 순서**입니다.

| # | 제목 | 경로 | 핵심 개념 |
|---|------|------|-----------|
| 7 | 피루브산 산화 | 피루브산 → 아세틸 CoA → 시트르산 | 물질대사는 효소 반응이 이어진 경로 |
| 8 | TCA 회로 전반부 | 아세틸 CoA → … → 석시닐 CoA | 탈탄산(CO₂)과 산화(NADH) |
| 9 | 후반부 · 경쟁적 억제 | 석시닐 CoA → … → 옥살아세트산 | 기질 수준 인산화, FADH₂, 말론산의 경쟁적 저해 |
| 10 | 한 바퀴 | 아세틸 CoA → … → 옥살아세트산 | 한 바퀴 수지 예측(CO₂ 2, NADH 3, FADH₂ 1, ATP 1, H₂O 2) |

화면 오른쪽의 **TCA 회로 지도**가 분자의 현재 위치와 탄소 수를 보여 줍니다. **생성물 장부**는 부산물을 실시간으로 셉니다.
각 부의 첫 스테이지(1, 7)는 처음부터 열려 있으므로, 생명과학 수업에서는 2부부터 바로 시작할 수 있습니다.

각 스테이지가 끝나면 **"설명해 보기"** 서술 문항에 답합니다. 결과 화면에서 기록을 JSON 파일로 저장하거나 요약 텍스트를 복사해 제출할 수 있습니다.
기록에는 실패 원인별 합계가 들어갑니다. 원인은 기질 불일치, 변성, pH 부적합, 저온, 효소 없이 에너지 부족입니다. 이 합계를 **오개념 신호**로 활용할 수 있습니다.

## 파일 구조

```
index.html          화면
css/style.css       스타일(라이트/다크)
js/data.js          기질·효소·스테이지 데이터 (스테이지 추가는 여기서)
js/parser.js        eval 없는 안전한 수식 파서
js/engine.js        판정 엔진(순수 함수, 브라우저·Node 공용)
js/game.js          화면 제어·애니메이션·기록
tests/verify-stages.js  모든 스테이지가 목표 발사 수 안에 풀리는지 자동 검증
tests/e2e.js        브라우저에서 전 스테이지 실제 플레이 검증(Playwright)
docs/teacher-guide.md   교사용 안내: 학습 설계 근거·수업안·단순화 목록·참고문헌
```

## 스테이지 추가·수정

`js/data.js`의 `STAGES` 배열에 객체를 추가합니다. 좌표계는 x 0~30, y −10~10입니다.
각 스테이지에는 모범 해법 `solution`을 반드시 넣고 아래 명령으로 검증하세요.
`solution`은 학생 화면에 보이지 않습니다.

```bash
node tests/verify-stages.js
```

## 배포 (GitHub Pages)

`.github/workflows/deploy-pages.yml`이 포함되어 있습니다. `main` 또는 작업 브랜치에 푸시하면 자동으로 배포됩니다.
처음 한 번은 저장소의 **Settings → Pages → Source**를 **GitHub Actions**로 설정해야 할 수 있습니다.

## 라이선스와 저작권

원작 게임의 이름, 그래픽, 캐릭터는 사용하지 않았습니다. 빌려 온 것은 "수식 그래프 = 탄도"라는 메커니즘뿐이고, 화면과 소재는 모두 새로 만들었습니다.
